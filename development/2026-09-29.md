### Layout

```
src/rfd3_pipeline/
  structure.py    loading, chain selection, sequences, CA matching
  contig.py       contig grammar, output numbering, length, hotspot renumbering
  config.py       campaign YAML schema; all validation not needing coordinates
  metrics/        ipsae, interface, rmsd, geometry -- numbers, never verdicts
  spec/           resolve.py (campaign x structure), design.py (reading designs back)
tests/            225 tests, incl. against the checked-in alphaV/beta3 input
```

Layering is innermost-first: `structure` depends on nothing, `contig` is a leaf
over it, and both `config` and `spec` build on `contig`. That ordering is what
lets the campaign schema parse contigs without an import cycle.

## Upstream findings (verified against source, not docs alone)

- **`--use_msa_server` does not cache**, despite its own help text. `run_alphafold.py:1728`
  calls `fill_missing_msas` on every invocation; `--cache_dir` is JAX compile
  only. Left on, this pipeline would POST every designed binder sequence to
  api.colabfold.com, once per prediction.
- **`fill_missing_msas` only skips chains whose MSA is already set.** A binder
  left at `None` is batched into both the unpaired *and* paired queries. It must
  be explicitly suppressed (`unpaired_msa=">query\n<seq>\n"`, `paired_msa=""`).
- **Optimus's MSA cache key collides**: keyed on `f"{prefix}_{mode}"` with the
  caller's directory as prefix, so two sequences sharing a directory resolve to
  one cached tarball. Its download timeout is also 6.02 s, too short for a large
  tarball.
- **Seed flags differ per model, not just in name.** esmfold2/boltz2 take an
  explicit `--seeds a,b,c`; af3_jax takes `--num_seeds N` and *generates* them,
  so the concrete seeds are readable only from its output.
- **`--variant` means different things per kit**: esmfold2 picks a model+MSA
  combination; af3_jax picks a checkpoint (`p2` = OpenFold3 ported weights).
- **Kit modes exit 3 rather than falling back**, and `--config` cards are
  `h100|h200|a100` only. So GPU and card must agree — hence `kit_config` being
  derived from `gpu` rather than configured.
- **Per-call startup is ~25 s in every mode** (`boltz2/README.md:144`), which is
  why folding steps map over *chunks* rather than individual sequences.
- **Compiled kernels are cached per machine and keyed by input shape.** On
  ephemeral Modal containers that cache is empty every time unless it is on a
  volume or baked in, and variable binder lengths mean bucketing matters.

## Campaign findings (alphaV/beta3)

- **`length` was wrong in both versions of the YAML.** The contig gives
  100-120 + 177 + 242 = **519-539**; the file said 510-570, whose range was also
  60 wide where the designed segment is 20.
- **The input has five chains, not three.** A/B/C protein plus four Mn(2+) in
  chains D and E. Measured coordination:

  | Metal | Coordinated by | To RGD Asp79 | Identity |
  |---|---|---|---|
  | E703 | **A79(ASP)**, C10, C12, C109 | **2.12 A** | MIDAS |
  | E704 | C12, C15, C16, C140 | 7.71 A | ADMIDAS |
  | E705 | C47, C104, C106, C108, C109 | 5.90 A | SyMBS |
  | D1004 | B139-B147 | 41.42 A | alphaV propeller |

  The RGD aspartate completes E703's coordination sphere at bonding distance, so
  scaffolding RGD without it would omit the motif's principal interaction. Now
  `ligand: "E703"`. D1004 is excluded on evidence.
- **Only one metal can be requested as the file stands.** RFD3 raises on more
  than one ligand residue per chain (`input_parsing.py:696-706`), and E703/704/705
  all sit on chain E. The full beta3 triad needs them split onto separate chains.
- **Ligands do not affect `length`** — it constrains the contig, and
  `_append_ligand` runs after the contig is built.
- **`ligand` is split on `,` *or* `-`**, so `"E703-705"` reads as a range.
  List instances separately.
- **Hotspot renumbering is the identity for this campaign**, because the contig
  takes both targets whole and in order. That makes it a poor sole test fixture —
  a completely broken implementation would pass. Non-identity cases are tested
  synthetically (offset starts, reordered chains).

## Design decisions worth remembering

- **`length` is derived and never emitted.** It is optional given a contig, and a
  second copy is a second thing to keep in sync.
- **Per-model facts live in one `MODEL_CAPABILITIES` table.** Before that,
  `boltz2` fell through validation entirely and accepted `variant` and
  `target_template` silently. A new model is one row; a missing row is a KeyError
  at import.
- **Metrics return numbers, never verdicts.** Thresholds and pass/fail belong to
  a single gate layer so the set of gates exists as data in one place.
- **Chain identity is always passed in.** Nothing in `metrics/` encodes "binder
  is A, targets are B onward"; `ResolvedSpec.target_chain_map` carries
  input→output explicitly, because a contig listing targets out of order renames
  them and anything keyed by chain would otherwise hand the wrong MSA to the
  wrong chain.
- **`ResolvedCampaign` holds plain data only.** It has to cross a Modal boundary;
  steps needing coordinates load from `structure_path`. `to_dict()` is what
  writes `campaign.resolved.yaml`.
- **`match_ca` pairs on (chain, res_id), not file order.** Optimus's
  length-assertion approach silently mis-pairs whenever two programs order chains
  differently.
- **In-process ipSAE, not the CLI.** ~480 x 6 calls per campaign; the CLI needs a
  process spawn and two temp files each.

## Review pass (four angles: reuse, simplification, efficiency, altitude)

Applied. Highlights:

- `binding_interface` allocated a dense contact mask and used two 1-D reductions
  off it — 2.6 MB today but **92 MB at 3000 residues**. Switched to the neighbour
  index form after verifying both reductions match exactly.
- ipSAE used `np.ma` in the inner loop: measured **7.7x slower** than the
  equivalent `np.where`, for the same answer. Chain blocks are contiguous, so
  `np.ix_` was copying where a slice views.
- The two target-aligned RMSDs recomputed an identical match and superposition;
  `target_superposition` now does it once.
- Deleted: hand-rolled `radius_of_gyration` (biotite ships it), `prefactor`/
  `exponent` parameters nothing passed, `ResolvedSpec.components` (zero readers),
  a duplicate residue-key regex, a `kit_config` field that only let you restate a
  derived value and be told you were wrong.
- `load_structure` now delegates format dispatch to biotite and expands gzip to a
  temp copy, so there is no extension table to maintain.

One agent claim rejected: `sampled_contig` is documented upstream
(`input.md:130,152`), not invented — the speculative multi-path search collapsed
to the one documented path rather than being deleted.
